# Permissions & roles

Boardchestrator organises access as **orgs → projects → teams**, and permission is deny-by-default: a member can do exactly what their role grants.

## Levels

- **Org** — owns projects and teams. Org-level pages (people, roles, settings, audit, usage, API keys, wiki, skills) are scoped here.
- **Project** — holds the board, backlog, reports, sprints, triggers, templates, and task pages.
- **Team** — the people doing the work; team pages cover membership and settings.

## Roles

A role is a named set of permissions. The org owner role (`*`) can do everything. Other roles grant specific capabilities — for example, a "Member" role that can see and move tasks but not manage settings.

## Editing roles

Open **Roles** under org settings to create or edit a role. You control exactly which capabilities a role carries, and who holds it. Memberships and invites are managed from the **People** page.
